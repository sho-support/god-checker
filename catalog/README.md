## ソース・信頼性方針
1. 一次情報：メーカー公式サイト、公式資料、確認可能なプレスリリース。
2. 二次情報：P-WORLD等は導入予定/機種登録情報の照合。詳細スペックは一次情報と突き合わせる。
3. 各機種に `sources`, `lastVerified`, `specStatus` を必須とする。
4. 未確認/噂/先行情報は確定扱いせず、原則シミュレーター生成対象から除く。
5. 機種名称・著作権表記を除き、他サイトの本文・画像・ロゴを無断転載しない。情報取得の利用条件・ロボット規約・アクセス頻度を確認。
6. 機種の導入/設置状況は時点で変わるため、導入予定日の経過だけで「全国のホールに設置中」と断定しない。

## 牙狼12のモデル（確定情報＋概数）
- 通常図柄揃い 1/437.49、ガロチャージ 1/1749.97。別イベントとして抽選し、合算約1/349.99。
- 図柄揃い：1500個払出し。50%で極限7500バトルへ。
- バトル：50%成功で7500個払出し＋LT、失敗で1500個払出し＋通常。
- LT：7500個継続約25%、1500個継続約51%、1500個終了約24%。合計100%になる丸め済みの簡易モデル。
- 実機の保留/演出/右打ち特殊ケース/隠れた内部処理まで同一とは主張しない。
- [メーカー公式](https://www.sansei-rd.co.jp/p_garo_archive/archive/p_garo12_ok.html) / [P-WORLD](https://www.p-world.co.jp/machine/database/10305) / [必勝本](https://p.hisshobon.jp/machine/4570/1/110370)

## 完成までの実装順序
1. 既存サイトのPC・スマホでの実ブラウザ10回以上の巡回（画面・導線・ボタン・SEO・数値・フォーム等）。検査ログを残す。
2. 機種データの独立したスキーマ、機種別URL、変更履歴、根拠URLの検証ロジックを用意する。
3. ホール設置台の対象基準と対象時点を定義し、メーカー/人気機種/新台の機種一覧を拡張する。名称ゆれや別スペックを別ID管理。
4. 確率エンジンを状態遷移（通常、確変、ST、時短、LT、チャレンジ、転落、残保留、上位AT等）と抽選イベント（図柄揃い、チャージ、小当たり、確率変化、振分、出玉）に分離する。
5. ST回数・小当り後の状態・右打ち/通常の抽選、残保留、ラウンド別払い出し、上乗せを実機ごとに定義し、解析データのない抽選は推定と明記する。
6. 自動新台発見: 適法で安定した一次情報フィード・利用許諾API等を調査し、定期GitHub Actionsで差分発見→項目チェック→新規JSON作成→自動PR→検証→公開。十分確実な項目だけ自動公開する。
7. SEO（メタ説明、canonical、構造化データ、サイトマップ）、検索・更新履歴、スマホ表示、アクセシビリティ、負荷、広告ポリシーを検証する。
8. 本番反映前に全機種データの整合検査とシミュレーションの長時間/偏り試験を実施する。

## 運用上の注意
- GitHub Pagesは静的サイト。定時更新にはGitHub Actions等が必要（予定時刻からの遅延・失敗あり）。
- 自動取得元の権利/許諾と数値誤りが最重要のリスク。無検証の情報をAIが補完し、正しい値として公開してはいけない。
- 旧サイトと新ポータルのブランド・公開位置は、本番反映前に決める。
- ギャンブルの結果・利益の保証なし。18歳未満の利用や過度の遊技を推奨しない。
